# 🌾 농부(Farmer) 미션 마스터 플랜: "대지의 관리자"

## 1. 미션 진행 메커니즘: [진화형 미션]

광부와 마찬가지로 **Chain System**을 적용합니다. 초기 단계는 단순 수확이지만, 상위 단계로 갈수록 **고품질 작물 생산**과 **가공(요리)** 능력을 요구합니다.

- **구조:** `Sprout` (새싹) → `Green` (녹색) → `Harvest` (수확) → `Golden` (황금) → `Master` (장인)
    
- **특이점:** 농부는 **계절(Season)**이나 **날씨**의 영향을 받는 미션이 포함됩니다.

## 2. 카테고리 A의 핵심 시스템 구현 상세 (Developer Note)

단순 노동을 방지하고 '시스템'으로 느끼게 하기 위한 개발 포인트입니다.

### ① 재파종(Replanting) 감지 로직

- **개요:** 유저가 작물을 캐고 바로 심는 행위를 '숙련된 농부의 행동'으로 간주합니다.
    
- **구현:**
    
    1. `BlockBreakEvent` 발생 시 해당 블록 위치(Location)와 시간(Timestamp)을 `Map<Location, Long>`에 임시 저장합니다.
        
    2. `BlockPlaceEvent` 발생 시, 해당 위치가 Map에 존재하고, `(현재 시간 - 저장된 시간) < 3000ms (3초)` 이며, 심은 아이템이 해당 작물의 씨앗이라면 "재파종 성공"으로 처리합니다.
        

### ② 독 묻은 감자 폐기 (Trash Disposal)

- **개요:** 마인크래프트의 '꽝' 아이템인 독 묻은 감자를 처리하는 미션.
    
- **구현:**
    
    - **방법 A (간단):** 인벤토리에 독 감자가 있는 상태에서 특정 명령어 `/farmer trash` 입력 시 일괄 삭제하며 카운트.
        
    - **방법 B (리얼):** 플레이어가 `용암(Lava)`이나 `선인장` 혹은 `아이템 액자(쓰레기통)`에 독 감자 아이템을 던지거나 넣어서 소멸되는 `ItemDespawnEvent` 혹은 `InventoryClickEvent`를 감지.
        

### ③ 범위 수확 및 도구 인챈트 감지

- **개요:** 바닐라 인챈트(행운, 섬세한 손길)와 커스텀 도구의 효과를 구분합니다.
    
- **구현:**
    
    - `BlockBreakEvent`에서 `player.getInventory().getItemInMainHand()`를 호출하여 `ItemMeta`와 `Enchantment`를 검사합니다.
        
    - 미션 조건이 `Fortune III`라면, 해당 인챈트 레벨을 확인 후 드롭량을 계산하거나 미션 카운트를 증가시킵니다.
        

### ④ 작물 성장 단계(Age) 체크 (필수)

- **개요:** 다 자라지 않은 작물을 캐는 꼼수를 방지합니다.
    
- **구현:**
    
    - `BlockData`를 `Ageable`로 캐스팅하여 `ageable.getAge() == ageable.getMaximumAge()` 인지 반드시 확인해야 카운트가 올라갑니다.

## 2. 카테고리 B의 핵심 시스템 구현 상세 (Developer Note)

이 단계부터는 '플레이어의 직접 행동'과 '월드의 상호작용'을 구분하는 것이 가장 중요합니다.

### ① 날씨 및 환경 감지 (Weather Check)

- **로직:**
    
    - `BlockBreakEvent` 발생 시 `player.getWorld().hasStorm()`이 `true`인지 확인합니다.
        
    - 동시에 `block.getLightFromSky()`가 15인지 확인하여, 지붕이 없는 **'야외(Outdoor)'**임을 검증해야 합니다. (동굴에서 비 오는 날 농사짓는 꼼수 방지)
        
    - **팁:** 비 오는 날에는 `CustomCropDrop`의 품질(Quality) 가중치를 1.5배 설정하여 유저들이 비가 오면 농장으로 뛰쳐나가게 유도합니다.
        

### ② 사막 농사 (보습 비료 로직)

- **문제점:** 마인크래프트 기본 로직상 물이 없으면 경작지(Farmland)는 흙으로 마릅니다.
    
- **해결책:**
    
    1. 유저가 `보습 비료` 아이템을 경작지에 우클릭(`PlayerInteractEvent`)합니다.
        
    2. 해당 블록의 `PersistentDataContainer`에 `key: "is_hydro_gel", value: true`를 저장하고, 파티클 효과를 줍니다.
        
    3. `BlockFadeEvent`(경작지가 흙으로 변함)를 캔슬(Cancel)합니다. 단, 해당 블록이 `is_hydro_gel` 데이터를 가지고 있을 때만.
        
    4. 이를 통해 물 없이도 경작지가 유지되는 '사막 농법'이 구현됩니다.
        

### ③ 스마트 팜 감지 (간접 파괴)

- **문제점:** 플레이어가 손으로 캐지 않고 물이나 피스톤으로 수확하면 `BlockBreakEvent`의 주체(Player)가 없습니다.
    
- **해결책 (Owner Tracking):**
    
    - 농작물을 심을 때(`BlockPlaceEvent`), 해당 블록 위치에 **심은 사람의 UUID**를 메타데이터로 저장합니다.
        
    - 블록이 물리적 요인(물, 피스톤)으로 파괴될 때(`BlockFromToEvent` 등), 저장된 UUID를 불러와 해당 플레이어의 미션 카운트를 올립니다. (단, 플레이어가 접속 중일 때만)
        
    - **부하 최적화:** 모든 블록에 UUID를 박는 게 부담스럽다면, 특정 '영역(Region)' 단위로 주인을 설정하는 방식(예: WorldGuard 연동)을 권장합니다.
        

### ④ 변이(Mutation) 시스템

- **로직:**
    
    - `변이 비료`를 주고 수확할 때 `Random`을 돌립니다.
        
    - 당근 수확 시 1% 확률로 **'황금 당근'**이 드롭되거나, 감자 수확 시 0.5% 확률로 **'자이언트 포테이토(머리 장식)'**가 드롭되게 합니다.
        
    - 이는 농부 유저들에게 '가챠(Gacha)'의 재미를 선사합니다.

## 2. 카테고리 C의 핵심 시스템 구현 상세 (Developer Note)

요리 및 가공 시스템은 '플러그인'의 역할이 매우 큽니다. 바닐라 조합법의 한계를 넘는 로직이 필요합니다.

### ① 품질 계승 (Quality Inheritance) 로직

- **개요:** 좋은 재료를 썼는데 일반 음식이 나오면 유저는 실망합니다.
    
- **구현:**
    
    - **커스텀 조합법 이벤트(`PrepareItemCraftEvent`)**를 활용합니다.
        
    - 조합대(Matrix)에 올라간 재료 아이템들의 PDC(Quality 수치)를 검사합니다.
        
    - _(예: 밀★3 + 밀★3 + 밀★3 = 빵★3)_
        
    - 결과 아이템(`Result`)의 `ItemMeta`에 평균 등급을 부여하고, 이름도 변경합니다. (예: `§6[★3] 고소한 빵`)
        
    - **주의:** 바닐라 레시피와 겹치지 않도록 커스텀 NBT 태그가 있는 재료만 이 로직을 타게 해야 합니다.
        

### ② 오크통 숙성 시스템 (Barrel Aging)

- **개요:** 오크통을 '양조기'처럼 사용합니다.
    
- **구현:**
    
    1. 플레이어가 오크통에 특정 재료(밀+물+효모)를 넣고 문을 닫습니다(`InventoryCloseEvent`).
        
    2. 레시피가 맞다면, 오크통 블록의 PDC에 `start_time: (timestamp)`와 `status: "aging"`을 기록합니다.
        
    3. 플레이어가 다시 열었을 때(`InventoryOpenEvent` or `Interact`), `(현재 시간 - 시작 시간)`을 계산합니다.
        
    4. 시간이 충분히 지났다면 내부 아이템을 '맥주'로 교체(setItem)합니다.
        
    5. 너무 오래 방치하면 '상한 술(식초)'로 변하게 하여 타이밍을 맞추는 재미를 줍니다.
        

### ③ 음식 버프 효과 (Buff Stats)

- **개요:** 요리에 RPG 요소를 부여합니다.
    
- **구현:**
    
    - `PlayerItemConsumeEvent` 발생 시 먹은 아이템의 NBT를 확인합니다.
        
    - `quality: 3` 데이터가 있다면 `player.addPotionEffect(Speed, 20*60, 1)` (1분간 신속) 등의 효과를 부여합니다.
        
    - 이를 통해 농부 유저는 단순 식량 공급자가 아니라 **'포션 제작자(Buffer)'**로서의 지위를 얻게 됩니다.

## 2. 카테고리 D의 핵심 시스템 구현 상세 (Developer Note)

전설 등급 미션은 밸런스 붕괴를 막으면서도 확실한 보상을 줘야 하므로, 정교한 **확률 제어**와 **데이터 관리**가 필수입니다.

### ① 잭팟(Jackpot) 확률 및 천장 시스템 (Pity System)

- **문제점:** 순수 운(0.01%)에 맡기면, 운 없는 유저는 평생 달성 못 하고 이탈합니다.
    
- **해결책:** **'실패 보정(Fail Stack)'**을 도입합니다.
    
    - 플레이어의 `PDC`에 `harvest_fail_stack`을 저장합니다.
        
    - 수확 시마다 스택이 +1 됩니다.
        
    - 기본 확률은 0.01%지만, 스택이 1,000 쌓이면 확률이 0.1%로, 10,000 쌓이면 1%로 점진적 증가합니다.
        
    - 황금 작물이 뜨면 스택은 0으로 초기화됩니다.
        

### ② 커스텀 텍스처 및 모델링 (Resource Pack)

- **필수 요소:** '황금 밀', '드래곤 스테이크'가 일반 아이템과 똑같이 생겼다면 감동이 없습니다.
    
- **구현:**
    
    - `CustomModelData`를 적극 활용합니다.
        
    - 황금 밀: 기존 밀 텍스처에 금색 테두리와 반짝이는 파티클 효과 추가.
        
    - 트랙터: 마인카트(Minecart) 모델을 트랙터로 변경하여 탑승 가능한 수확기 구현.
        

### ③ 전 서버 알림 및 파티클 (Broadcasting & Vfx)

- **효과:** 전설 미션 달성은 개인의 기쁨을 넘어 서버의 축제여야 합니다.
    
- **구현:**
    
    - **Action:** 황금 작물 수확 시 `LightningEffect`(대미지 없는 번개)를 치게 하고, `Firework`를 터뜨립니다.
        
    - **Chat:** `[System] 🌟 농부 <OOO>님이 전설의 [황금 당근]을 수확했습니다!` 메시지 송출.
        
    - **Sound:** 웅장한 효과음 (`UI_TOAST_CHALLENGE_COMPLETE` 등) 재생.
        

### ④ 유효성 검증 (Anti-Abuse)

- **어뷰징 방지:** 설치/파괴 반복을 통한 확률 조작을 막아야 합니다.
    
- **로직:**
    
    - 작물이 **자연적으로 다 자란 상태(Naturally Grown)**인지 체크하는 `source_flag`를 심습니다.
        
    - 뼛가루나 비료로 강제 성장시킨 작물은 전설 아이템 드롭률을 대폭 낮추거나(Penalty), 드롭되지 않게 설정합니다.
        
    - 오직 '시간'을 들여 자란 작물에서만 전설이 등장하도록 유도합니다.

# 🛠️ 농부 미션 시스템 개발 가이드 (Developer's Blueprint)

## 1. 핵심 데이터 구조 (Data Architecture)

농부 시스템의 핵심은 **"이 작물이 어떤 환경에서 자랐는가?"**를 추적하는 것입니다. 마인크래프트의 일반 블록(Block)은 NBT 데이터를 저장하지 못하므로(TileEntity 제외), 별도의 데이터 관리 전략이 필요합니다.

### A. PDC (PersistentDataContainer) 활용 전략

아이템(Item)과 블록(Block)의 데이터를 다르게 처리해야 합니다.

1. **아이템(ItemMeta):** 수확된 작물, 요리, 비료 아이템.
    
    - `quality` (Integer): 1~5성 등급.
        
    - `crafter_uuid` (String): 누가 생산했는지(전설 미션용).
        
    - `timestamp` (Long): 숙성 시작 시간(양조용).
        
2. **경작지/블록(Location):** 비료가 뿌려진 땅.
    
    - 모든 땅에 데이터를 넣으면 렉이 발생하므로, **"비료가 뿌려진 땅"**만 `Chunk`의 PDC 혹은 별도 DB(SQLite/MySQL)에 `Location`을 Key로 저장합니다.
        

### B. CustomBlockData 클래스 (예시)

서드파티 라이브러리(CustomBlockData 등)를 쓰거나 청크 PDC를 씁니다.

Java

```
// 비료 데이터 저장 예시 (Chunk PDC 활용 권장)

    // 이렇게 하면 블록 단위 TileEntity를 생성하지 않아 서버 부하를 최소화함
}
```

## 2. 핵심 로직 구현 (Core Logic)

### ① 품질 결정 알고리즘 (Quality Algorithm)

수확 시(`BlockBreakEvent`), 아이템이 드롭되기 직전에 품질을 계산하여 아이템을 교체합니다.

> **공식:** `기본 확률` + `비료 보정` + `환경 보정(날씨/바이옴)` + `농부 스킬 보정` = **최종 품질(Star)**

Java

```
public ItemStack calculateCropDrop(Player player, Block block) {
    double qualityScore = Math.random() * 100; // 0~100 기본 주사위

    // 1. 비료 보정 (저장된 데이터 확인)
    String fertilizer = getFertilizerAt(block.getLocation());
    if (fertilizer != null && fertilizer.equals("QUALITY_COMPOST")) {
        qualityScore += 20; // 20% 가산점
    }

    // 2. 환경 보정 (비 오는 날 야외)
    if (player.getWorld().hasStorm() && block.getLightFromSky() == 15) {
        qualityScore += 10;
    }

    // 3. 등급 판정
    int star = 1;
    if (qualityScore > 95) star = 4;      // 전설
    else if (qualityScore > 85) star = 3; // 최상급
    else if (qualityScore > 60) star = 2; // 상급

    // 4. 아이템 생성 및 NBT 주입
    ItemStack crop = new ItemStack(Material.WHEAT);
    ItemMeta meta = crop.getItemMeta();
    
    // PDC에 품질 저장
    NamespacedKey key = new NamespacedKey(plugin, "crop_quality");
    meta.getPersistentDataContainer().set(key, PersistentDataType.INTEGER, star);
    
    // 이름 변경 & 로어 추가 (예: [★★★] 싱싱한 밀)
    updateItemDisplay(meta, star); 
    
    crop.setItemMeta(meta);
    return crop;
}
```

### ② 요리 품질 계승 (Crafting Inheritance)

`PrepareItemCraftEvent`에서 재료의 품질 평균값을 계산합니다.

Java

```
@EventHandler
public void onPrepareCraft(PrepareItemCraftEvent event) {
    CraftingInventory inv = event.getInventory();
    ItemStack[] matrix = inv.getMatrix();
    
    int totalQuality = 0;
    int ingredientCount = 0;
    boolean isCustomCooking = false;

    for (ItemStack item : matrix) {
        if (item != null && item.hasItemMeta()) {
            Integer quality = item.getItemMeta().getPersistentDataContainer()
                .get(new NamespacedKey(plugin, "crop_quality"), PersistentDataType.INTEGER);
            
            if (quality != null) {
                totalQuality += quality;
                ingredientCount++;
                isCustomCooking = true;
            }
        }
    }

    if (isCustomCooking && ingredientCount > 0) {
        int avgQuality = totalQuality / ingredientCount; // 평균 등급 (내림)
        ItemStack result = event.getRecipe().getResult().clone();
        // 결과물에 avgQuality 적용 로직 수행
        inv.setResult(applyQualityToResult(result, avgQuality));
    }
}
```

### ③ 재파종 감지 (Replanting Logic)

유저 편의성과 매크로 방지를 동시에 잡는 로직입니다.

Java

```
// 임시 저장소: <블록위치, 파괴시간>
private Map<Location, Long> breakHistory = new HashMap<>();

@EventHandler
public void onBlockBreak(BlockBreakEvent e) {
    if (isCrop(e.getBlock().getType())) {
        breakHistory.put(e.getBlock().getLocation(), System.currentTimeMillis());
    }
}

@EventHandler
public void onBlockPlace(BlockPlaceEvent e) {
    Location loc = e.getBlock().getLocation();
    if (breakHistory.containsKey(loc)) {
        long breakTime = breakHistory.get(loc);
        if (System.currentTimeMillis() - breakTime < 3000) { // 3초 이내
            // 미션 카운트: 재파종 성공!
            missionManager.addProgress(e.getPlayer(), "replant_mission", 1);
            breakHistory.remove(loc); // 중복 방지
        }
    }
}
```

## 4. 최적화 및 보안 (Optimization & Anti-Abuse)

### 🚀 성능 최적화 (Lag Prevention)

1. **Event Filtering:** `BlockBreakEvent`는 서버에서 가장 많이 일어나는 이벤트 중 하나입니다. `if (!isCrop(block.getType())) return;` 처럼 농작물이 아니면 즉시 리턴하여 연산을 줄여야 합니다.
    
2. **Particle Batching:** 비료 효과나 성장 파티클을 줄 때, 매 틱마다 주지 않고 일정 주기(Scheduler)로 모아서 처리하거나 클라이언트 사이드 처리만 유도해야 합니다.
    
3. **DB Caching:** 비료 데이터를 매번 DB에서 읽지 않고, `HashMap<Chunk, Map<Location, Data>>` 형태로 메모리에 캐싱해야 합니다.
    

### 🛡️ 어뷰징 방지 (Exploit Fixes)

1. **설치-파괴 반복 (Place-Break Loop):**
    
    - **해결:** 플레이어가 직접 설치한 블록에는 PDC 태그 `placed_by_player: true`를 붙입니다.
        
    - 미션 체크 시 이 태그가 **없는** 작물(자연 생성 or 성장 과정 완료)만 카운트합니다.
        
    - 단, '재파종 미션'은 예외입니다.
        
2. **자동 농장 (AFK Farming):**
    
    - 물/피스톤 수확 시 경험치나 희귀 아이템 드롭률을 0%로 설정합니다.
        
    - "농부의 낫" 등 특정 도구를 손에 들고 있을 때만 보너스가 적용되도록 합니다.
