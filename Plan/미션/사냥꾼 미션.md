특히 사냥꾼은 **'전리품 가공(도축)'**과 **'현상수배(용병)'**라는 독특한 경제 모델을 가지므로, 이를 미션에 적극 반영했습니다.

# 🏹 사냥꾼(Hunter) 미션 마스터 플랜: "야생의 지배자"

## 1. 미션 진행 메커니즘: [진화형 미션]

단순 학살(Grinding)을 방지하기 위해, 미션은 **특정 몬스터**, **처치 방식(무기/도구)**, **환경(밤/지옥)**, **상태(엘리트)**를 복합적으로 요구하는 형태로 진화합니다.

- **구조:** `Novice` (견습) → `Ranger` (추적자) → `Slayer` (학살자) → `Beast Master` (조련사) → `Predator` (포식자)
    
- **핵심:** 사냥꾼은 **'도감(Knowledge)'**을 채우고 **'엘리트 몬스터'**를 사냥하는 것이 주된 목표입니다.

## 🛠️ 개발자 구현 가이드 (Implementation Note)

### 1. 조건 체크 (ConditionChecker) 강화

단순 킬 카운트 외에 `Context`를 확인해야 합니다.

Java

```
@EventHandler
public void onMobKill(EntityDeathEvent event) {
    Player hunter = event.getEntity().getKiller();
    LivingEntity mob = event.getEntity();
    
    // 1. 크리퍼 폭발 방지 킬 확인
    if (mob.getType() == EntityType.CREEPER) {
        // 크리퍼가 터지는 중이 아니었는지 확인 (state check)
        Creeper creeper = (Creeper) mob;
        if (creeper.getFuseTicks() > 0) {
            // 터지기 직전 처치! (보너스 점수 or 미션 인정)
        }
    }
    
    // 2. 아기 좀비 확인
    if (mob instanceof Zombie) {
        if (!((Zombie) mob).isAdult()) {
             missionManager.addProgress(hunter, "baby_zombie_kill", 1);
        }
    }
    
    // 3. 비 오는 날 엔더맨
    if (mob.getType() == EntityType.ENDERMAN) {
        if (hunter.getWorld().hasStorm()) {
             missionManager.addProgress(hunter, "rainy_enderman", 1);
        }
    }
}
```

## 🛠️ 개발자 구현 가이드 (Implementation Note)

### 1. 헤드샷 판정 (Headshot Logic)

마인크래프트는 기본적으로 헤드샷 판정이 없으므로, `EntityDamageByEntityEvent`에서 직접 계산해야 합니다.

Java

```
@EventHandler
public void onArrowHit(EntityDamageByEntityEvent event) {
    if (event.getDamager() instanceof Arrow && event.getEntity() instanceof LivingEntity) {
        Arrow arrow = (Arrow) event.getDamager();
        LivingEntity victim = (LivingEntity) event.getEntity();
        
        double arrowY = arrow.getLocation().getY();
        double eyeY = victim.getEyeLocation().getY();
        
        // 화살 높이가 눈 높이 기준 ±0.5 블록 이내면 헤드샷 인정
        if (Math.abs(arrowY - eyeY) < 0.5) {
            event.setDamage(event.getDamage() * 1.5); // 데미지 1.5배 보너스
            player.sendMessage("§c§lHEADSHOT!");
            
            // 미션 카운트 증가 로직 호출
            missionManager.addProgress((Player) arrow.getShooter(), "headshot_kill", 1);
        }
    }
}
```

### 2. 백스탭 판정 (Backstab Logic)

벡터 내적을 사용하여 두 엔티티가 같은 방향을 보고 있는지 확인합니다.

Java

```
public boolean isBackstab(Player attacker, LivingEntity victim) {
    Vector playerDir = attacker.getLocation().getDirection().setY(0).normalize();
    Vector mobDir = victim.getLocation().getDirection().setY(0).normalize();
    
    // 두 벡터의 각도가 좁을수록(같은 곳을 볼수록) 내적 값은 1에 가까움
    // 대략 60도 각도 내에서 뒤를 쳤을 때 인정 (값 > 0.5)
    return playerDir.dot(mobDir) > 0.5;
}
```

// 1. 도감 키 생성
NamespacedKey bestiaryKey = new NamespacedKey(plugin, "bestiary_data");

// 2. 몬스터 처치 시 업데이트
public void updateBestiary(Player player, EntityType mobType) {

    String currentData = data.getOrDefault(bestiaryKey, PersistentDataType.STRING, "");

    if (!currentData.contains(mobType.name())) {

    }
}

}

## 🛠️ 개발자 구현 가이드 (Implementation Note)

### 1. 솔로 킬 검증 (Solo Kill Verification)

보스를 여러 명이 때리면 안 되므로, `DamageMap`을 활용하여 검증합니다.

Java

```
// 보스 엔티티의 UUID를 키로, 데미지 입힌 플레이어 목록을 저장
private Map<UUID, Set<UUID>> bossDamageLog = new HashMap<>();

@EventHandler
public void onBossDamage(EntityDamageByEntityEvent event) {
    if (event.getEntity() instanceof Wither || event.getEntity() instanceof EnderDragon) {
        if (event.getDamager() instanceof Player) {
            UUID bossId = event.getEntity().getUniqueId();
            bossDamageLog.putIfAbsent(bossId, new HashSet<>());
            bossDamageLog.get(bossId).add(event.getDamager().getUniqueId());
        }
    }
}

@EventHandler
public void onBossDeath(EntityDeathEvent event) {
    UUID bossId = event.getEntity().getUniqueId();
    if (bossDamageLog.containsKey(bossId)) {
        Set<UUID> attackers = bossDamageLog.get(bossId);
        
        // 공격자가 단 1명이어야 함
        if (attackers.size() == 1) {
            UUID hunterId = attackers.iterator().next();
            Player hunter = Bukkit.getPlayer(hunterId);
            // 미션 클리어 처리
            missionManager.completeMission(hunter, "solo_boss_kill");
        }
        bossDamageLog.remove(bossId); // 메모리 정리
    }
}
```

### 3. 전설 무기 능력 구현 (Instant Kill)

`EntityDamageByEntityEvent`에서 체력 비율을 계산합니다.

Java

```
@EventHandler
public void onSlayerHit(EntityDamageByEntityEvent event) {
    if (event.getDamager() instanceof Player && event.getEntity() instanceof LivingEntity) {
        Player player = (Player) event.getDamager();
        ItemStack hand = player.getInventory().getItemInMainHand();
        
        // NBT 또는 PDC로 'The Slayer' 무기인지 확인
        if (isLegendaryWeapon(hand)) {
            LivingEntity victim = (LivingEntity) event.getEntity();
            double healthPercent = victim.getHealth() / victim.getAttribute(Attribute.GENERIC_MAX_HEALTH).getValue();
            
            // 보스가 아니고, 체력이 20% 이하라면 즉사
            if (!(victim instanceof Boss) && healthPercent <= 0.2) {
                event.setDamage(9999); // 즉사 데미지
                player.getWorld().spawnParticle(Particle.SWEEP_ATTACK, victim.getLocation(), 1);
                player.sendMessage("§c[집행] 처형했습니다.");
            }
        }
    }
}
```

## 2. 🖥️ 핵심 로직 구현 (Core Logic)

사냥꾼 미션 구현을 위해 반드시 처리해야 할 3가지 주요 리스너 로직입니다.

### A. 엘리트 몬스터 판별 (PDC 활용)

일반 몹과 엘리트 몹을 구분하기 위해 이름(Display Name)을 체크하는 것은 위험합니다(조작 가능). 반드시 **NBT/PDC**를 확인해야 합니다.

Java

```
// 1. 몬스터 스폰 시 (1% 확률로 엘리트 지정)
@EventHandler
public void onMobSpawn(CreatureSpawnEvent event) {
    if (event.getSpawnReason() == SpawnReason.NATURAL && Math.random() < 0.01) {
        LivingEntity mob = event.getEntity();
        
        // PDC에 'is_elite' 태그 부여
        PersistentDataContainer data = mob.getPersistentDataContainer();
        data.set(new NamespacedKey(plugin, "is_elite"), PersistentDataType.BYTE, (byte) 1);
        
        // 시각적 효과 (이름표, 파티클)
        mob.setCustomName("§c[Elite] §f" + mob.getName());
        mob.setCustomNameVisible(true);
        mob.getAttribute(Attribute.GENERIC_MAX_HEALTH).setBaseValue(mob.getMaxHealth() * 2); // 체력 2배
    }
}

// 2. 몬스터 처치 시 (미션 체크)
public boolean isElite(LivingEntity mob) {
    PersistentDataContainer data = mob.getPersistentDataContainer();
    return data.has(new NamespacedKey(plugin, "is_elite"), PersistentDataType.BYTE);
}
```

### B. 헤드샷 판정 알고리즘 (Headshot Logic)

마인크래프트는 헤드샷 개념이 없으므로, 직접 계산해야 합니다.

Java

```
@EventHandler
public void onArrowHit(EntityDamageByEntityEvent event) {
    if (event.getDamager() instanceof Arrow && event.getEntity() instanceof LivingEntity) {
        Arrow arrow = (Arrow) event.getDamager();
        LivingEntity victim = (LivingEntity) event.getEntity();
        
        // 화살의 Y좌표와 피격자의 눈 높이(EyeLocation) Y좌표 비교
        double arrowY = arrow.getLocation().getY();
        double eyeY = victim.getEyeLocation().getY();
        
        // 오차 범위 0.5블록 이내면 헤드샷 인정
        if (Math.abs(arrowY - eyeY) < 0.5) {
            // 효과음 및 메시지
            if (arrow.getShooter() instanceof Player) {
                Player shooter = (Player) arrow.getShooter();
                shooter.playSound(shooter.getLocation(), Sound.ENTITY_ARROW_HIT_PLAYER, 1f, 2f); // 띵! 소리
                
                // 미션 진행도 업데이트
                missionManager.addProgress(shooter, "headshot_kill", 1);
            }
            event.setDamage(event.getDamage() * 1.5); // 데미지 보너스
        }
    }
}
```

### C. 도감 데이터 저장 (No Database)

MySQL 없이 유저의 도감(Bestiary) 데이터를 저장하려면 플레이어의 `PDC`를 사용하는 것이 가장 효율적입니다.

Java

```
// 데이터 저장 포맷: JSON String 또는 Delimiter String
// 예: "ZOMBIE:150,SKELETON:40,CREEPER:10"

public void addKillCount(Player player, EntityType type) {
    NamespacedKey key = new NamespacedKey(plugin, "bestiary_data");
    PersistentDataContainer pdc = player.getPersistentDataContainer();
    
    // 기존 데이터 로드
    String dataStr = pdc.getOrDefault(key, PersistentDataType.STRING, "");
    Map<EntityType, Integer> kills = parseBestiaryData(dataStr); // 문자열 파싱 함수
    
    // 카운트 증가
    kills.put(type, kills.getOrDefault(type, 0) + 1);
    
    // 저장
    pdc.set(key, PersistentDataType.STRING, serializeBestiaryData(kills));
    
    // 도감 레벨업 체크
    checkBestiaryLevelUp(player, type, kills.get(type));
}
```

## 3. 🛡️ 어뷰징 방지 (Anti-Exploit)

사냥꾼은 '몹 타워(Mob Grinder)'나 '스포너'를 이용한 꼼수에 가장 취약합니다. 이를 방지하기 위한 필터링이 필수적입니다.

1. **스폰 원인 필터링 (SpawnReason Check):**
    
    - `EntityDeathEvent`에서 해당 몹의 `SpawnReason`을 확인하려 하면, 이미 죽은 뒤라 메타데이터가 사라질 수 있습니다.
        
    - **해결:** 몹이 스폰될 때(`CreatureSpawnEvent`), `SPAWNER`, `SPAWNER_EGG`, `BREEDING`으로 태어난 몹에게는 PDC로 `no_reward: true` 태그를 붙여야 합니다.
        
    - 죽일 때 이 태그가 있으면 경험치/돈/미션 카운트를 지급하지 않습니다.
        
2. **동일 IP/위치 반복 킬 방지:**
    
    - 플레이어가 한 자리(1x1)에 서서 마우스만 클릭하는 매크로를 방지합니다.
        
    - `PlayerMoveEvent` 없이 `Kill` 발생 시 플레이어의 `Location`을 저장해두고, **"최근 1분간 같은 좌표에서 10마리 이상 처치"** 시 경고를 띄우거나 보상을 0으로 만듭니다.

## 5. 💰 타 직업과의 연계 요약 (Economy Loop)

개발 시 가장 신경 써야 할 **경제 순환 고리**입니다.

1. **Hunter -> Farmer:**
    
    - `뼈(Bone)` 납품 -> 농부의 `비료` 재료.
        
    - `썩은 살점` -> 가공 -> `가죽` -> 농부의 `아이템 주머니` 제작 재료.
        
2. **Hunter -> Adventurer:**
    
    - `거미 눈`, `화약` 납품 -> 탐험가의 `폭죽(신호탄)` 및 `독 포션` 재료.
        
    - `현상수배지` 구매 -> 탐험가가 발견한 던전 좌표를 사냥꾼이 구매하여 소탕.
        
3. **Hunter -> Miner:**
    
    - `화살` 소비 -> 광부가 캐낸 `부싯돌`과 `깃털(닭장에서 생산)` 대량 구매.
        
    - `무기 수리` -> 광부(대장장이)에게 의뢰.
