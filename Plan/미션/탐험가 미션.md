# 🗺️ 탐험가(Adventurer) 미션 마스터 플랜: "지평선의 기록자"

## 1. 미션 진행 메커니즘: [진화형 미션]

단순히 "얼마나 걸었느냐"가 아니라, **"무엇을 발견했느냐"**와 **"얼마나 정확히 기록했느냐"**를 평가합니다.

- **구조:** `Wanderer` (방랑자) → `Scout` (정찰대) → `Ranger` (레인저) → `Cartographer` (지도 제작자) → `Columbus` (개척자)
    
- **핵심:** 탐험가는 **좌표(Coordinates)**와 **바이옴(Biome)**, 그리고 **구조물(Structure)**을 찾는 것이 주된 목표입니다.

## 🛠️ 개발자 구현 가이드 (Implementation Notes)

### 1. 퍼포먼스 최적화 (Distance Check)

탐험가는 계속 움직이는 직업이므로 `PlayerMoveEvent` 로직이 무거우면 서버 전체가 렉이 걸립니다.

Java

```
// 나쁜 예: 매 틱마다 거리 계산 및 DB 저장
@EventHandler
public void onMove(PlayerMoveEvent e) {
    saveDistanceToDatabase(e.getPlayer(), e.getFrom().distance(e.getTo()));
}

// 좋은 예: 청크가 바뀔 때만, 혹은 비동기 스케줄러 활용
@EventHandler
public void onChunkChange(PlayerMoveEvent e) {
    if (e.getFrom().getChunk() == e.getTo().getChunk()) return; // 같은 청크 내 이동 무시
    
    // 비동기로 처리
    Bukkit.getScheduler().runTaskAsynchronously(plugin, () -> {
         updateExplorationData(e.getPlayer());
    });
}
```

### 2. 지도(Map) 데이터 처리

- **지도 100% 채움 감지:** `MapView`의 `getRenderers()`를 통해 픽셀 데이터가 모두 채워졌는지 확인하는 것은 연산량이 많습니다. 대신, 플레이어가 지도를 들고 움직일 때 `explored_chunks` 카운트를 NBT로 저장하여 일정 수치 이상(예: 128x128 픽셀 중 90% 이상)일 때 완료 처리하는 방식이 효율적입니다.
    

### 3. 바이옴 및 구조물 감지

- `Biome`은 클라이언트와 서버 간 동기화가 잘 되어 있으므로 `player.getLocation().getBlock().getBiome()`으로 즉시 체크 가능합니다.
    
- **구조물 발견**은 `world.locateNearestStructure` 메소드를 남발하면 안 됩니다. 플레이어가 **새로운 청크에 진입했을 때(ChunkLoad)** 해당 청크가 구조물 데이터를 포함하고 있는지(`chunk.getStructureReferences()`) 체크하는 것이 가장 서버 친화적입니다.

## 🛠️ 개발자 구현 가이드 (Implementation Notes)

### 1. 망원경 레이트레이싱 (Spyglass RayTrace)

- **성능 이슈:** `rayTraceEntities`는 연산 비용이 꽤 듭니다. `PlayerInteractEvent`에서 매번 호출하기보다, 플레이어가 망원경을 들고 있는 상태(`isHandRaised() && Material.SPYGLASS`)인지 확인 후, 0.5초(10틱) 간격의 스케줄러로 체크하는 것이 좋습니다.
    
- **거리 제한:** 서버 렌더 거리(View Distance) 이상은 감지할 수 없습니다. 최대 거리는 `100 ~ 150` 블록으로 제한하는 것을 권장합니다.
    

### 2. 바이옴 캡슐 (NBT Data)

- 수집한 공기 아이템은 겉보기엔 다 같은 '포션 병'이지만, 내부 데이터는 달라야 합니다.
    
    Java
    
    ```
    // 예시 코드 (Pseudo)
    ItemStack biomeCapsule = new ItemStack(Material.POTION);
    PotionMeta meta = (PotionMeta) biomeCapsule.getItemMeta();
    meta.setDisplayName("§a정글의 공기");
    meta.setColor(Color.GREEN); // 물병 색깔 변경
    meta.getPersistentDataContainer().set(key, PersistentDataType.STRING, "JUNGLE");
    biomeCapsule.setItemMeta(meta);
    ```
    
- 이렇게 저장된 NBT(`JUNGLE`)를 기반으로 건축가가 사용 시 어떤 효과를 줄지 결정합니다.
    

### 3. 나침반 소리 로직 (Sound Feedback)

- `PlayerItemHeldEvent`나 `MoveEvent`를 통해 나침반을 들고 있는지 확인합니다.
    
- 타겟(보물상자)과의 거리를 `distanceSq` (제곱 거리)로 계산하여 루트 연산을 피합니다.
    
- 거리에 따라 `player.playSound()`의 `pitch` 값을 조절하면(0.5 ~ 2.0), 거리가 가까울수록 **"띠.. 띠. 띠! 띠!!!"** 하고 긴박한 소리를 낼 수 있습니다.
    

### 4. 어뷰징 방지

- **발광(Eagle Eye):** 같은 몬스터에게 반복해서 스킬을 써서 경험치를 얻는 것을 막기 위해, `Entity`의 메타데이터에 `already_spotted` 태그를 붙여야 합니다.
    
- **귀환석:** PvP 중 사용을 막으려면 `CombatTag` 플러그인과 연동하거나, 최근 데미지 입은 시간(`System.currentTimeMillis() - lastDamageTime`)을 체크해야 합니다.

## 🛠️ 개발자 구현 가이드 (Implementation Notes)

### 1. 좌표 스크롤 (Coordinate Scroll Item)

일반 종이나 책에 메타데이터를 입혀야 합니다.

Java

```
// 좌표 스크롤 생성 예시
public ItemStack createScroll(Player p, String name, Location loc, double price) {
    ItemStack scroll = new ItemStack(Material.PAPER);
    ItemMeta meta = scroll.getItemMeta();
    meta.setDisplayName("§b[좌표] " + name);
    List<String> lore = new ArrayList<>();
    lore.add("§7위치: " + loc.getBlockX() + ", " + loc.getBlockY() + ", " + loc.getBlockZ());
    lore.add("§7가격: §e" + price + " D");
    lore.add("§7발행자: " + p.getName());
    meta.setLore(lore);
    
    // PDC (PersistentDataContainer) 활용
    PersistentDataContainer data = meta.getPersistentDataContainer();
    data.set(new NamespacedKey(plugin, "coord_x"), PersistentDataType.INTEGER, loc.getBlockX());
    data.set(new NamespacedKey(plugin, "coord_z"), PersistentDataType.INTEGER, loc.getBlockZ());
    data.set(new NamespacedKey(plugin, "creator_uuid"), PersistentDataType.STRING, p.getUniqueId().toString());
    
    scroll.setItemMeta(meta);
    return scroll;
}
```

### 2. 배달 미션의 '텔레포트 방지'

배달 미션은 **'이동 과정'**이 핵심이므로, 편법(텔포)을 막아야 합니다.

- **허용:** `PlayerMoveEvent` (걷기, 달리기), `VehicleMoveEvent` (말, 보트, 카트)
    
- **차단:** `PlayerTeleportEvent`
    
    - `TeleportCause.COMMAND`, `PLUGIN` -> **미션 실패** 처리.
        
    - `TeleportCause.ENDER_PEARL` -> 쿨타임 증가 or 패널티 부여 (선택 사항).
        
    - `TeleportCause.NETHER_PORTAL` -> **허용** (지옥을 이용한 지름길은 전략 요소).
        

### 3. 경제 연동 (Vault & Shop)

- **스크롤 판매:** 플레이어가 만든 스크롤을 `ChestShop`이나 `AuctionHouse` 플러그인에 올릴 수 있도록 호환성을 체크해야 합니다.
    
- 자체 상점 플러그인을 쓴다면, `ItemStack`의 `isSimilar` 검사에서 `PDC` 데이터까지 비교하는지 확인해야 합니다. (일반 종이와 좌표 스크롤이 섞이면 안 됨)
    

### 4. 어뷰징 방지

- **좌표 돌려쓰기:** A가 산 스크롤을 B에게 공짜로 보여주는 것을 막을 순 없지만, 스크롤을 **'1회용 소모품'**으로 만들면 정보의 가치가 유지됩니다. (사용 시 사라지고, 채팅창에 좌표가 뜨게 함)
    
- **자작 거래:** 부계정을 이용해 자기 스크롤을 사고파는 행위를 막기 위해 `Buyer UUID != Creator UUID` 체크를 넣어야 합니다.

## 🛠️ 개발자 구현 가이드 (Implementation Notes)

### 1. 최초 발견 시스템 (Server First Logic)

싱글톤(Singleton) 데이터 관리가 필요합니다.

Java

```
// config.yml 예시
server_records:
  ancient_city:
    discovered: true
    discoverer: "Steve"
    date: "2025-01-01 12:00:00"
  mansion:
    discovered: false
```

- **로직:** 플레이어가 특정 구조물 바운딩 박스에 들어갔을 때, `config.getBoolean("server_records.ancient_city.discovered")`가 `false`라면 최초 발견 보상을 지급하고 `true`로 변경합니다. 이미 `true`라면 일반 방문 보상만 지급합니다.
    

### 2. 고대 도시 잠입 (Sneaking Mechanic)

- 스컬크 슈리커(Shrieker)가 비명을 지르는 이벤트(`BlockPreExpode` or Custom Logic)를 감지해야 합니다.
    
- 미션 시작 시 `shrieker_trigger_count = 0`으로 초기화하고, 슈리커가 울릴 때마다 카운트를 올립니다. 카운트가 0인 상태로 상자를 열어야 성공입니다.
    

### 3. 좌표 및 구조물 데이터 최적화

- **Paper API 활용:** 최신 PaperMC 서버라면 `StructureLocater`를 비동기(`Async`)로 사용할 수 있습니다.
    
- **캐싱(Caching):** 한 번 발견된 구조물의 좌표는 서버 메모리에 캐싱하여, 다른 플레이어가 근처에 갔을 때 다시 무거운 `locate` 연산을 하지 않도록 합니다.
    

### 4. 정보의 가치 보존

- 이 **'카테고리 D'**에서 발견한 좌표들은 **'카테고리 C(정보 상인)'**의 핵심 매물이 됩니다.
    
- 탐험가가 고대 도시 좌표를 발견하면, 이를 **[봉인된 좌표 스크롤: 고대 도시]** 아이템으로 만들어 경매장에 올릴 수 있게 시스템을 연결합니다. 이는 사냥꾼(Hunter)들이 고가의 장비를 맞추기 위해 반드시 구매해야 하는 아이템이 됩니다.

## 3. 💡 핵심 로직 구현 포인트 (Logic & Code Snippets)

### A. 지도 데이터 처리 (Map Data Handling)

지도가 얼마나 밝혀졌는지 확인하는 것은 NMS(Net.Minecraft.Server) 접근이 필요할 수 있으나, Spigot API로 근사치를 계산할 수 있습니다.

- **지도 완성도 체크 로직:**
    
    Java
    
    ```
    public boolean isMapFilled(MapView view) {
        // 지도의 픽셀 데이터 접근 (성능 주의)
        // 128x128 픽셀 중 '탐험된 색상'이 아닌 0(투명/미탐험)이 얼마나 적은지 체크
        int exploredPixels = 0;
        // *실제 구현 시에는 픽셀을 전수조사하기보다, 
        // 플레이어가 해당 지도를 들고 움직인 청크 수(PDC 기록)를 카운트하는 것이 효율적입니다.*
        return exploredPixels >= (128 * 128 * 0.9); // 90% 이상 채워짐
    }
    ```
    

### B. 망원경 레이트레이싱 (Spyglass RayTrace)

플레이어가 바라보는 시선 끝에 무엇이 있는지 감지합니다.

- **이글 아이(Eagle Eye) 구현:**
    
    Java
    
    ```
    @EventHandler
    public void onSpyglassUse(PlayerInteractEvent e) {
        if (e.getItem().getType() != Material.SPYGLASS) return;
        if (!e.getAction().isRightClick()) return;
    
        Player p = e.getPlayer();
        // 최대 100블록 거리의 엔티티 감지
        RayTraceResult result = p.getWorld().rayTraceEntities(
            p.getEyeLocation(), 
            p.getEyeLocation().getDirection(), 
            100.0, 
            entity -> entity instanceof Monster // 몬스터만 타겟
        );
    
        if (result != null && result.getHitEntity() != null) {
            Entity target = result.getHitEntity();
            target.setGlowing(true); // 발광 효과 부여
    
            // 10초 후 발광 해제 (Scheduler)
            Bukkit.getScheduler().runTaskLater(plugin, () -> {
                target.setGlowing(false);
            }, 200L);
        }
    }
    ```
    

### C. 배달 미션과 텔레포트 감지 (Delivery & Anti-Cheat)

배달 미션의 핵심은 **"직접 이동"**입니다. 꼼수(텔레포트)를 막아야 합니다.

- **배달 미션 매니저:**
    
    Java
    
    ```
    public class DeliveryMission {
        private UUID playerUUID;
        private long startTime;
        private Location destination;
    
        // 텔레포트 감지 리스너
        @EventHandler
        public void onTeleport(PlayerTeleportEvent e) {
            if (!e.getPlayer().getUniqueId().equals(playerUUID)) return;
    
            // 허용된 텔레포트: 네더 포탈, 엔더 포탈
            if (e.getCause() == TeleportCause.NETHER_PORTAL || 
                e.getCause() == TeleportCause.END_PORTAL) {
                return; 
            }
    
            // 그 외(명령어, 엔더진주 등)는 미션 실패 처리
            failMission(e.getPlayer(), "텔레포트 사용 감지됨! 배달 실패.");
        }
    }
    ```
    

### D. 좌표 스크롤과 PDC (Persistent Data Container)

아이템에 좌표 정보를 안전하게 저장합니다. `Lore`(설명)에만 의존하면 유저가 조작할 수 있습니다.

- **스크롤 데이터 저장:**
    
    Java
    
    ```
    public ItemStack createCoordinateScroll(Player creator, Location loc) {
        ItemStack item = new ItemStack(Material.PAPER);
        ItemMeta meta = item.getItemMeta();
    
        PersistentDataContainer data = meta.getPersistentDataContainer();
        // 좌표 데이터 저장 (Integer)
        data.set(new NamespacedKey(plugin, "coord_x"), PersistentDataType.INTEGER, loc.getBlockX());
        data.set(new NamespacedKey(plugin, "coord_y"), PersistentDataType.INTEGER, loc.getBlockY());
        data.set(new NamespacedKey(plugin, "coord_z"), PersistentDataType.INTEGER, loc.getBlockZ());
        data.set(new NamespacedKey(plugin, "world_uid"), PersistentDataType.STRING, loc.getWorld().getUID().toString());
    
        // 원작자 저장 (로열티 지급용)
        data.set(new NamespacedKey(plugin, "creator_uuid"), PersistentDataType.STRING, creator.getUniqueId().toString());
    
        item.setItemMeta(meta);
        return item;
    }
    ```

## 4. 🚀 성능 최적화 (Performance Tuning)

탐험가는 서버의 광활한 지역을 로딩하므로, 서버 렉의 주범이 될 수 있습니다.

1. **청크 로딩 최소화:**
    
    - `world.locateNearestStructure` (구조물 찾기 API)는 메인 스레드에서 돌리면 서버가 멈춥니다. 반드시 **`CompletableFuture`**나 **`AsyncScheduler`**를 사용하여 비동기로 처리해야 합니다.
        
    - 구조물 발견 미션은 플레이어가 이동할 때마다 체크하지 말고, **청크가 변경될 때(`PlayerMoveEvent`에서 청크 좌표 비교)** 한 번만 체크합니다.
        
2. **거리 계산 최적화:**
    
    - `Location.distance(Location)` 함수는 제곱근 연산(`Math.sqrt`)을 하므로 무겁습니다.
        
    - 단순 거리 비교(범위 내에 있는지)만 필요하다면 **`distanceSquared()`**를 사용하세요. (예: `distSq < 100 * 100`)
        
3. **데이터베이스 제외:**
    
    - 요청하신 대로 MySQL 없이 구현하려면, 유저의 탐험 기록(발견한 구조물 목록 등)을 `player.getPersistentDataContainer()`에 JSON 문자열이나 Byte Array로 압축하여 저장하는 것을 권장합니다.

## 5. 🛡️ 어뷰징 방지 (Exploit Prevention)

1. **좌표 돌려쓰기:**
    
    - 좌표 스크롤은 사용 시(우클릭 시) **소모(1개 차감)**되게 하여 정보의 가치를 유지합니다.
        
    - 이미 등록된 좌표(본인이 만든 것)는 다시 등록해도 경험치를 주지 않습니다.
        
2. **배달 릴레이 (이어달리기):**
    
    - A가 퀘스트를 받고 B가 도착지점에 대기하다가 아이템만 넘겨주는 행위.
        
    - 해결책: 퀘스트 시작 시 지급되는 '소포' 아이템에 `owner_uuid`를 박아두고, 도착 지점의 NPC는 **퀘스트 수락자와 아이템 소유자가 일치할 때만** 완료를 받아줍니다.
        
3. **무한 구조물 발견:**
    
    - 마을 하나를 찾고 나갔다 들어오기를 반복하는 행위.
        
    - 해결책: `List<String> discoveredStructures`를 유저 데이터에 저장하여, `Unique ID`(구조물 좌표 해시값 등)가 중복되면 보상을 주지 않습니다.
