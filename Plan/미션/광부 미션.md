### 🛠️ 개발자(User)를 위한 구현 가이드 (Implementation)

1. 미션 데이터 관리 (YAML 구조)

미션 이름과 설명은 최대한 마인크래프트 세계관에 어울리게 설정 파일(missions/miner.yml)에 작성합니다.

YAML

```
# missions/miner.yml
chains:
  fuel_supply: # 미션 ID
    tier_1:
      display_name: "&f[광부] &e대장장이의 친구"
      lore:
        - "&7대장간의 화로가 꺼져가고 있습니다."
        - "&7석탄을 구해 불씨를 살려주세요."
      objective: "BREAK:COAL_ORE:64"
      rewards:
        - "money give %player% 200"
        - "give %player% torch 64"
      next_mission: "tier_2"
    tier_2:
      display_name: "&f[광부] &6검은 보석"
      lore:
        - "&7더 많은 열기가 필요합니다."
        - "&7깊은 곳의 석탄은 더 오래 탄다고 합니다."
      objective: "BREAK:COAL_ORE:500"
```

**2. 진화 시스템 (Evolution Logic)**

- 플레이어가 `tier_1` 미션을 완료하면, 보상을 지급함과 동시에 해당 플레이어의 미션 데이터를 `tier_2`로 **교체(Update)**합니다.
    
- 이로 인해 플레이어는 "내가 성장하고 있다"는 느낌을 받게 되며, 단순 반복 미션도 '스토리'처럼 느끼게 됩니다.
    

이어서 **[카테고리 B. 기술/신박함]**에 대한 구체화를 진행할까요? 여기서는 단순 노동이 아닌 '광부의 스킬'과 '상황 판단'을 요구하는 미션들을 다룹니다.
---

네, 사용자님의 피드백을 반영하여 현대적이거나 이질적인 느낌을 배제하고, 마인크래프트 야생(Vanilla)의 모험심을 자극하는 **[카테고리 B. 기술/기교 (Skill & Finesse)]** 미션을 상세 설계했습니다.

1. 감정(Identify) 시스템 로직

미지의 광석을 감정할 때 결과물을 결정하는 로직입니다.

Java

```
// ForgeManager.java (Pseudo)
public ItemStack identifyOre(Player player) {
    // 1. 비용 차감 (Vault)
    economy.withdrawPlayer(player, 50.0);
    
    // 2. 미션 진행도 업데이트 (Chain 3: 타운의 후원자)
    missionManager.addProgress(player, "forge_spender", 50);

    // 3. 확률 테이블 (Weighted Random)
    double roll = Math.random();
    ItemStack result;
    if (roll < 0.01) result = new ItemStack(Material.ANCIENT_DEBRIS); // 1%
    else if (roll < 0.10) result = new ItemStack(Material.DIAMOND);   // 9%
    else result = new ItemStack(Material.COAL);                       // 나머지
    
    // 4. 미션 진행도 업데이트 (Chain 1: 진실 / Chain 1-Lv2: 황금의 눈)
    missionManager.addProgress(player, "identify_count", 1);
    if (result.getType() == Material.DIAMOND) {
        missionManager.addProgress(player, "identify_jackpot", 1);
    }
    
    return result;
}
```

public ItemStack createAlloy() {

}

### 🛠️ 개발자(User)를 위한 구현 가이드 (Implementation)

이 카테고리는 조건 체크가 까다롭기 때문에 **리스너(Listener) 최적화**가 중요합니다.

1. 워든/엔티티 감지 최적화

매 블록 파괴마다 getNearbyEntities를 호출하면 서버 부하가 생길 수 있습니다.

- **해결:** `Deep Dark` 바이옴일 때만 체크하거나, 워든이 스폰된 상태(`EntitySpawnEvent`로 관리)일 때만 해당 로직이 돌도록 조건을 거세요.
    

**2. 체력/화염 체크 코드 (Java Example)**

Java

```
@EventHandler
public void onHardcoreMine(BlockBreakEvent event) {
    Player player = event.getPlayer();
    
    // 1. [사선의 경계] 미션 체크
    if (player.getHealth() <= 1.0) { // 반 칸 이하 (1 HP)
        if (event.getBlock().getType() == Material.ANCIENT_DEBRIS) {
            missionManager.completeMission(player, "near_death_mining");
        }
    }

    // 2. [지옥의 심장] 미션 체크
    if (player.getFireTicks() > 0) { // 불타는 중
        // 머리가 용암에 잠겼는지 확인 (Material.LAVA)
        if (player.getEyeLocation().getBlock().getType() == Material.LAVA) {
             if (event.getBlock().getType() == Material.ANCIENT_DEBRIS) {
                 missionManager.completeMission(player, "inferno_mining");
             }
        }
    }
}
```

3. 보상 아이템 (PDC 활용)

전설 보상인 **'대지의 심장'**이나 **'용암 장화'**는 단순히 이름만 바꾼 아이템이 아니라, 실제 기능을 부여해야 합니다.

- **용암 장화:** `PlayerMoveEvent`에서 발밑이 용암일 때 `Damage` 이벤트를 캔슬하거나 속도를 줄이지 않게 로직 처리.
    
- **대지의 심장:** 인벤토리에 있으면 `PotionEffectType.FAST_DIGGING` (성급함 II) 무한 적용.

## 3. 🧩 시스템 로직 구현 가이드 (Backend)

`DreamWork` 플러그인 내부의 핵심 클래스 구조입니다.

### A. MissionManager (중앙 관리자)

이벤트 리스너에서 데이터를 받아 미션 진행도를 체크하고 업데이트합니다.

Java

```
public class MissionManager {

    // 블록 파괴 시 호출
    public void addProgress(Player player, Material blockType, int amount) {
        User user = plugin.getUserManager().getUser(player);
        
        // 유저가 진행 중인 모든 광부 미션 루프
        for (MissionChain chain : user.getMinerMissions()) {
            Mission currentTier = chain.getCurrentTier();
            
            // 1. 목표 대상(Target)이 맞는지 확인
            if (currentTier.getTarget() == blockType) {
                
                // 2. 조건(Condition) 체크 (하드코어/기술 미션용)
                if (!checkConditions(player, currentTier.getConditions())) {
                    continue; 
                }

                // 3. 진행도 업데이트
                int newProgress = user.addMissionProgress(chain.getId(), amount);
                
                // 4. 액션바 출력
                sendActionBar(player, currentTier, newProgress);

                // 5. 완료 체크
                if (newProgress >= currentTier.getAmount()) {
                    completeMission(player, chain);
                }
            }
        }
    }

    // 미션 완료 처리 (진화 시스템)
    private void completeMission(Player player, MissionChain chain) {
        Mission tier = chain.getCurrentTier();
        
        // 보상 지급
        giveRewards(player, tier.getRewards());
        
        // 다음 단계(Next Tier)로 교체
        if (tier.hasNextTier()) {
            user.setMissionTier(chain.getId(), tier.getNextTierId());
            user.resetProgress(chain.getId()); // 카운트 0으로 초기화
            
            player.sendTitle("§6미션 완료!", "§7다음 단계: §e" + tier.getNextTierName());
            player.playSound(player.getLocation(), Sound.UI_TOAST_CHALLENGE_COMPLETE, 1f, 1f);
        } else {
            // 최종 단계 클리어 시
            user.setMissionCompleted(chain.getId());
        }
    }
}
```

### B. ConditionChecker (조건 확인기)

카테고리 B(기술)와 D(하드코어)를 위한 정밀 판독기입니다.

Java

```
public boolean checkConditions(Player player, List<String> conditions) {
    for (String cond : conditions) {
        // 예: "HP_BELOW:2" (체력 1칸 이하)
        if (cond.startsWith("HP_BELOW:")) {
            double limit = Double.parseDouble(cond.split(":")[1]);
            if (player.getHealth() > limit) return false;
        }
        
        // 예: "SKILL_ACTIVE:ORE_RADAR" (레이더 사용 중)
        if (cond.equals("SKILL_ACTIVE:ORE_RADAR")) {
            if (!plugin.getSkillManager().isRadarActive(player)) return false;
        }
        
        // 예: "IN_LAVA" (용암 속)
        if (cond.equals("IN_LAVA")) {
            if (player.getEyeLocation().getBlock().getType() != Material.LAVA) return false;
        }
    }
    return true;
}
```

## 4. 📌 개발 우선순위 (Roadmap)

1. **Backend (필수):**
    
    - `missions.yml` 로더 구현.
        
    - 플레이어 별 진행도(Progress) 저장 시스템 (FlatFile/PDC) 구축.
        
    - 기본적인 `BlockBreakEvent` 연동.
        
2. **Frontend (필수):**
    
    - 미션 확인용 GUI 구현.
        
    - 진행도 액션바(Action Bar) 출력 기능.
        
3. **Advanced (심화):**
    
    - `ConditionChecker` 구현 (체력, 시간, 스킬 상태 체크).
        
    - 진화(Evolution) 시 화려한 이펙트 및 보상 지급 로직.
        

이 가이드를 통해 광부 직업은 단순히 돌만 캐는 것이 아니라, **성장하고 진화하는 RPG스러운 경험**을 제공받게 됩니다. 구현 시 `conditions` 부분만 유연하게 설계하면, 추후 다른 직업(농부, 사냥꾼)에도 그대로 적용할 수 있습니다.
