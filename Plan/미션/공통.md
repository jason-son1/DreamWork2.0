기존의 5대 직업(광부, 어부, 농부, 사냥꾼, 탐험가)이 **"자원을 생산하고 가공하는 역할"**에 집중되어 있다면, 공통 미션(Common Missions)은 **"서버에 정착하여 살아가는 시민으로서의 의무와 유저 간 상호작용"**에 초점을 맞춰야 합니다.

`Project-DreamWork`의 핵심 철학인 "경제적 상호작용"과 "타운 중심의 생활"을 반영하여, **[DreamWork 시민 생활 계획표]**라는 컨셉의 공통 미션 프레임워크를 제안합니다.

# 📋 DreamWork 공통 미션 시스템 구상안

## 1. 기본 컨셉: "시민의 의무 (Duties of Citizenship)"

직업 미션이 '성장'과 '스펙업'을 위한 것이라면, 공통 미션은 서버 경제의 윤활유 역할을 합니다.

유저가 단순히 자기 직업만 파고드는 것을 방지하고, 타운 활동, 소비, 커뮤니티 참여를 유도하여 서버 전체의 활성화를 도모합니다.

---

## 2. 미션 분류 체계 (Category Framework)

공통 미션은 크게 **주기성(Routine)**, **경제(Economy)**, **사회(Social)**, **업적(Milestone)**의 4가지 축으로 나뉩니다.

|**분류**|**미션 명칭**|**초기화 주기**|**목적**|**핵심 타겟**|
|---|---|---|---|---|
|**A. 생활**|**성실한 하루**|일일 (Daily)|접속 유지 및 기본 활동|접속 시간, 채팅, 기본 섭취|
|**B. 경제**|**시장의 큰손**|주간 (Weekly)|재화 순환 및 소비 장려|상점 이용, 유저 거래, 경매|
|**C. 사회**|**타운의 기둥**|주간/시즌|타운 성장 및 협동|타운 세금, 건축 기여, 방문|
|**D. 특별**|**명예의 전당**|영구 (One-time)|장기 목표 및 칭호|누적 플레이, 종합 랭크|

---

## 3. 상세 미션 기획안 (Detailed Plan)

### A. 생활 루틴 (Routine): "건강한 신체에 건전한 정신"

서버에 접속해서 숨만 쉬어도(기본 활동만 해도) 달성 가능한 미션들입니다. 뉴비들의 정착을 돕습니다.

- **일일 미션 (Daily)**
    
    - **[출석 체크]**: 서버 접속 1회. (보상: 소량의 D)
        
    - **[생존의 기본]**: 음식 섭취 5회. (농부 생산품 소비 유도)
        
    - **[오늘의 뉴스]**: 전체 채팅 10회 입력.
        
    - **[근면 성실]**: 접속 시간 60분 달성.
        
- **주간 미션 (Weekly)**
    
    - **[생존 전문가]**: 일주일간 사망 횟수 3회 미만 유지 (하드코어 성향 반영).
        
    - **[만능 일꾼]**: 5대 직업 활동 중 3가지 이상 수행하기 (예: 광질 1회, 낚시 1회, 수확 1회).
        

### B. 경제 활동 (Economy): "돈은 돌아야 한다"

직업 미션으로 번 돈을 **쓰게 만드는** 미션입니다. 인플레이션을 방지하고 유저 간 거래를 강제합니다.

- **소비 장려 (Spending)**
    
    - **[로컬 푸드 애용]**: 다른 유저(농부)가 만든 요리 아이템 구매/섭취.
        
    - **[장비 렌탈/구매]**: 다른 유저(광부/대장장이)가 수리하거나 제작한 도구 사용.
        
    - **[납세의 의무]**: 타운 유지비(세금) 납부 완료.
        
- **거래 활성화 (Trading)**
    
    - **[시장 조사]**: 다른 유저의 개인 상점(ChestShop) 3곳 방문 및 구매.
        
    - **[물물 교환]**: 유저 간 직접 거래(Trade UI) 1회 성사.
        

### C. 사회 및 타운 (Social & Town): "함께 짓는 꿈"

`Towny` 플러그인과 연동하여 소속감을 고취시키는 미션입니다.

- **타운 활동**
    
    - **[영토 확장]**: 소속 타운의 `Town Block` 구매/확장에 기여 (기부).
        
    - **[이웃 방문]**: 동맹 타운 또는 다른 타운의 중심부(HomeBlock) 방문.
        
    - **[건축가의 꿈]**: 타운 내 블록 설치 100회 (건축 장려).
        

### D. 특별 목적 (Special): "드림워크의 전설"

시즌 이벤트나 서버 전체의 목표를 달성하기 위한 특수 미션입니다.

- **서버 투표 및 홍보**
    
    - **[서버의 얼굴]**: 서버 추천(Vote) 1회 참여. (보상: 드림 스톤 조각)
        
- **히든/이벤트**
    
    - **[보물 찾기]**: 운영자가 숨겨둔 특정 좌표나 표지판 찾기 (탐험가와 연계).
        
    - **[축제 준비]**: 서버 공용 구역 건축 재료 기부 (예: 스폰 지역 리모델링을 위해 돌 1,000개 기부).

## 4. 보상 체계 설계 (Reward Structure)

공통 미션의 보상은 직업 미션과 차별화되어야 합니다. 직업 경험치보다는 **편의성**과 **명예**에 집중합니다.

1. **시민 등급 점수 (Citizen Point - CP):**
    
    - 공통 미션을 깰 때마다 CP 획득.
        
    - CP가 쌓이면 **[시민 등급]**이 상승 (예: 방랑자 -> 거주민 -> 시민 -> 귀족).
        
    - 등급 혜택: 창고 슬롯 확장, 닉네임 칭호, 타운 내 구매 가능한 플롯 수 증가.
        
2. **드림 스톤 (Dream Stone):**
    
    - 주간 미션 올클리어 시 소량 지급. (직업 미션 외의 획득처 제공)
        
3. **버프 아이템 (Utility):**
    
    - 일일 미션 보상으로 **[활력의 포션]** (이동속도 증가 10분) 등, 직업 활동을 돕는 소모품 지급.

## 5. 기술적 구현 프레임워크 (Technical Implementation)

자체 플러그인(`DreamWork`) 내에서 이를 구현하기 위한 구조 제안입니다.

### 5.1 Config 구조 예시 (`common_missions.yml`)

YAML

```
daily_missions:
  reset_time: "00:00:00" # 매일 자정 초기화
  missions:
    daily_login:
      type: "LOGIN"
      amount: 1
      display_name: "출석 도장 쾅!"
      rewards:
        - "money 100"
        - "point 10" # 시민 점수
    eat_food:
      type: "CONSUME"
      material: "COOKED_BEEF" # 혹은 커스텀 아이템 ID
      amount: 5
      display_name: "든든한 한 끼"
      
weekly_missions:
  reset_day: "MONDAY"
  missions:
    town_tax:
      type: "TOWNY_TAX" # Towny API 연동 필요
      amount: 1
      display_name: "성실한 납세자"
```

### 5.2 필요한 리스너 및 연동 (Listeners & Hooks)

1. **PlayerJoinEvent:** 일일 접속 체크 및 자정 지난 경우 미션 초기화 로직 실행.
    
2. **PlayerItemConsumeEvent:** 음식 섭취 미션 카운팅.
    
3. **Towny Hooks:**
    
    - `TownAddResidentEvent`: 타운 가입 미션.
        
    - `TownClaimEvent`: 영토 확장 기여 확인.
        
    - 세금 납부의 경우 Towny API에서 이벤트를 제공하지 않는다면, `DreamWork` 경제 시스템에서 돈이 빠져나갈 때 로그를 확인(Tax 사유)하여 카운팅.
        
4. **Economy Hooks (Vault):**
    
    - 다른 유저에게 돈을 지불하는 행위(ChestShop 구매 등) 감지.

## 6. 결론 및 제안

이 공통 미션 체계는 **"직업이 없는 백수라도 서버에서 할 일이 있게 만드는 것"**이 핵심입니다.

- **초반:** 일일 미션을 통해 서버에 적응하고 기초 자금을 마련합니다.
    
- **중반:** 경제 미션을 통해 다른 직업 유저와 거래하며 직업 미션(합금, 요리 등)에 필요한 재료를 수급합니다.
    
- **후반:** 시민 등급을 올려 명예를 얻고, 타운을 성장시키는 리더가 됩니다.
    

이 틀을 바탕으로 각 주기별(일간/주간) 미션의 구체적인 수치만 밸런싱하시면 바로 적용 가능한 시스템이 될 것입니다.



제안하신 **공통 미션의 카테고리 A. [생활 루틴 (Routine)]**을 구체화한 상세 기획안입니다.

이 카테고리는 **"접속 유지(Retention)"**와 **"기초 소비(Basic Consumption)"**를 담당합니다. 유저가 서버에 접속해서 수행하는 가장 기초적인 행동(이동, 식사, 대화)에 의미를 부여하여, 자연스럽게 서버에 녹아들도록 설계했습니다.

# 📋 카테고리 A 상세 기획: "성실한 시민의 하루"

## 1. 기획 의도 (Concept & Purpose)

- **뉴비 정착 지원:** 갓 서버에 들어온 유저가 무엇을 해야 할지 모를 때, "일단 이것부터 하세요"라고 제시하는 가이드라인 역할을 합니다.
    
- **기초 경제 순환:** '배고픔'과 '활동'을 미션화하여, 농부(식량 생산)와 대장장이(도구 수리)가 생산한 기초 재화의 소비를 촉진합니다.
    
- **서버 활력 부여:** 잠수(AFK) 유저를 줄이고, 채팅과 이동을 장려하여 서버가 살아있는 느낌을 줍니다.

|**`daily_move`**|**[운동] 동네 한 바퀴**|걷기/달리기 거리 $1,000\text{m}$|$50\text{D}$ + **CP 5점**|잠수 방지. `Statistic.WALK_ONE_CM` 체크.|
|**`daily_sleep`**|**[휴식] 꿀잠**|침대에서 수면 1회|**채광/채집 속도 $\uparrow$ (10분)**|팬텀 스폰 억제 및 서버 시간 관리.|

### 🔍 상세 메커니즘: [건강] 미션의 차별화

단순히 아무거나 먹는 것이 아니라, **"농부가 생산한 가치"**를 소비해야 카운트됩니다.

- **인정 목록:** 빵, 스테이크, 황금 당근, 호박 파이, 생선 구이 등 (화로/제작을 거친 음식).
    
- **제외 목록:** 생 닭고기, 썩은 살점, 거미 눈, 사과(가공 전).
    
- **효과:** 초보 유저들이 농부 유저가 파는 "3성 빵"이나 "도시락"을 구매해야 할 동기를 부여합니다.

4. **사냥꾼:** 몬스터 10마리 처치.
    
5. **탐험가:** 새로운 청크 5곳 방문.

## 5. 이벤트 리스너 구현 가이드 (Implementation)

이 미션들을 구현하기 위해 필요한 주요 Bukkit API 이벤트입니다.

### 5.1 PlayerItemConsumeEvent (식사)

- **로직:**
    
    1. 이벤트 발생 시 `event.getItem().getType()` 확인.
        
    2. `material_whitelist`에 있는 아이템인지 대조.
        
    3. 맞다면 해당 유저의 `daily_eat` 카운트 $+1$.
        
    4. 목표 달성 시 알림 및 보상 지급.
        

### 5.2 PlayerStatisticIncrementEvent (이동)

- **최적화 주의:** 이동 통계는 매 틱마다, 혹은 매우 빈번하게 업데이트될 수 있습니다.
    
- **로직:**
    
    1. 이벤트마다 DB를 쓰면 서버 렉 유발.
        
    2. `Statistic.WALK_ONE_CM`이 증가할 때, **메모리에 캐싱된 값**만 업데이트.
        
    3. 일정 주기(예: 5분마다) 혹은 `PlayerQuitEvent` 시에만 DB/미션 진행도에 저장.
        
    4. 유저가 `/미션` 명령어를 칠 때 현재 통계 값을 불러와서 달성 여부 체크.
        

### 5.3 PlayerDeathEvent (주간 생존)

- **로직:**
    
    1. 유저 사망 시 `weekly_death_count` 변수 증가.
        
    2. `max_deaths`($3$회)를 초과하면 해당 주차의 미션 상태를 `FAILED`로 변경.
        
    3. 실패 메시지 출력: _"이번 주는 부상이 심해 시민 안전 보상을 받을 수 없습니다."_

## 6. 기대 효과 (Expected Outcome)

1. **"할 게 없어요" 방지:** 접속하자마자 기계적으로라도 해야 할 루틴(인사, 밥 먹기, 걷기)을 제공하여 플레이 지속성을 높입니다.
    
2. **소비재 수요 창출:** '요리된 음식'만 카운트하므로, 요리를 귀찮아하는 광부/사냥꾼 유저들이 농부 유저에게 빵이나 고기를 구매하게 됩니다.
    
3. **시민 등급의 기반:** 이 쉬운 미션들을 통해 `CP(Citizen Point)`를 차곡차곡 모으게 하여, 나중에 타운을 건설하거나 창고를 늘리는 상위 콘텐츠로 자연스럽게 유도합니다.
   
   
   

제안하신 **공통 미션의 카테고리 B. [경제 활동 (Economy)]**을 구체화한 상세 기획안입니다.

이 카테고리의 핵심은 **"인플레이션 억제"**와 **"직업 간 상호 의존성 강화"**입니다. 단순히 돈을 버는 것이 아니라, **"번 돈을 다른 유저에게 쓰도록"** 강제하거나 유도하여 경제가 고이거나 썩지 않고 순환하게 만듭니다.

# 💰 카테고리 B 상세 기획: "보이지 않는 손 (The Invisible Hand)"

## 1. 기획 의도 (Concept & Purpose)

- **직업 간 거래 강제:** 광부가 캔 광물로 돈을 벌면, 그 돈으로 농부의 요리를 사 먹고 사냥꾼의 전리품(가죽)을 사게 만듭니다.
    
- **화폐 회수 (Gold Sink):** 세금, 경매 수수료, 상점 이용 등을 통해 서버에 풀린 화폐(D)를 지속적으로 소각합니다.
    
- **상권 형성:** 유저들이 개인 상점(ChestShop)을 열고 홍보하게 만드는 동기를 부여합니다.

|**`eco_shopper`**|**[소비] 시장의 큰손**|**다른 유저** 상점에서 $5,000\text{D}$ 이상 구매|**CP 30점** + 랜덤 광물 박스|**ChestShop/QuickShop 연동.** 서버 상점이 아닌 유저 상점 이용만 카운트.|

### 🔍 상세 메커니즘: [로컬 푸드] & [시장의 큰손]

단순히 돈을 쓰는 게 아니라 **"누구에게"** 쓰느냐가 중요합니다.

- **Self-Transaction 방지:** 구매자와 판매자의 UUID가 같으면 카운트되지 않아야 합니다. (자전거래 방지)
    
- **품목 감지:** `eco_gourmet` 미션은 구매한 아이템의 `Material`이 `EDIBLE`(먹을 수 있는 것)인지 확인합니다.

## 5. 이벤트 리스너 및 연동 가이드 (Technical Implementation)

경제를 추적하기 위해서는 `Vault`뿐만 아니라 실제 상점 플러그인(`ChestShop` 등)의 이벤트를 잡아야 합니다.

### 5.1 ChestShopTransactionEvent (상점 구매)

- **플러그인:** ChestShop (또는 사용 예정인 상점 플러그인 API)
    
- **로직:**
    
    1. `TransactionEvent` 리스닝.
        
    2. `event.getTransactionType() == TransactionType.BUY` 확인 (유저가 산 경우).
        
    3. `event.getClient()` (구매자)와 `event.getOwner()` (판매자) 비교 -> **UUID가 다를 때만 진행.**
        
    4. `event.getPrice()`를 누적하여 `eco_shopper` 미션 카운트.
        
    5. `event.getStock()[0].getType().isEdible()` 체크 -> `eco_gourmet` 미션 카운트.
        

### 5.2 TownyTaxPaymentEvent (세금 납부)

- **플러그인:** Towny
    
- **주의:** Towny는 API가 복잡할 수 있습니다. 만약 직접적인 이벤트가 없다면 `Vault`의 출금 이벤트를 우회적으로 활용해야 합니다.
    
- **우회 로직 (Vault Hook):**
    
    1. `EconomyResponse withdrawPlayer(...)` 가 호출될 때,
        
    2. 출금 사유(Reason)나 대상 계좌가 'Towny' 혹은 'Town-Block-Tax'인지 문자열 파싱으로 확인. (가장 확실한 방법은 Towny 소스코드 내 이벤트를 확인하는 것입니다. 보통 `TownPreAddResidentEvent` 등과 달리 세금은 조용히 빠져나갑니다. 가장 쉬운 방법은 **Towny의 `pay_tax` 커맨드를 쳤을 때** 혹은 **하루 한 번 접속 시 `towny_tax_paid` 상태를 체크**하는 것입니다.)
        

### 5.3 PlayerDepositEvent (타운 입금)

- **로직:**
    
    1. 유저가 `/t deposit 1000` 명령어 실행 감지 (`PlayerCommandPreprocessEvent`).
        
    2. 혹은 Towny 이벤트 중 `TownAddMoneyEvent`가 있다면 활용.
        
    3. 가장 안전한 방법: 자체 플러그인에 `/dw donate town <amount>` 명령어를 만들고, 이 명령어가 내부적으로 `Towny` 뱅크에 돈을 넣고 미션을 클리어 처리하게 래핑(Wrapping)함.

## 6. 기대 효과 (Synergy)

1. **농부/광부/어부의 판매처 확보:**
    
    - 초보 농부가 열심히 농사지은 빵을 아무도 안 사주면 접게 됩니다.
        
    - `[로컬 푸드]` 미션이 있으면, 고수 유저들도 미션 클리어를 위해 뉴비의 빵을 사주게 됩니다. (낙수 효과)
        
2. **타운의 결속력 강화:**
    
    - `[타운의 후원자]` 미션을 통해 타운 은행에 돈이 쌓입니다.
        
    - 이 돈으로 타운장은 영토를 확장하고, 공용 건물을 지어 다시 유저들에게 혜택을 돌려줍니다.
        
3. **인플레이션 억제:**
    
    - 미션을 핑계로 유저들이 돈을 창고에 쌓아두지 않고 계속 쓰게 만듭니다. 돈은 돌아야 가치가 유지됩니다.
        

이 시스템은 **"유저가 유저를 돕는 구조"**를 시스템적으로 강제하여, 커뮤니티가 삭막해지지 않도록 윤활유 역할을 할 것입니다.





제안하신 **공통 미션의 카테고리 C. [사회 및 타운 (Social & Town)]**을 구체화한 상세 기획안입니다.

이 카테고리의 핵심은 **"소속감(Belonging)"**과 **"협동(Cooperation)"**입니다. 마인크래프트 서버가 '혼자 하는 게임'이 되지 않도록, 시스템적으로 유저들을 뭉치게 하고 서로의 마을을 구경하게 만들어 커뮤니티를 활성화합니다.

# 🤝 카테고리 C 상세 기획: "함께 짓는 꿈 (Building Together)"

## 1. 기획 의도 (Concept & Purpose)

- **타운의 성장 유도:** 타운이 커지려면 막대한 자금(Towny Upkeep)과 인력이 필요합니다. 미션을 통해 이를 자연스럽게 지원합니다.
    
- **유저 간 교류:** 다른 타운을 방문하게 하여 서버 내의 다양한 건축물을 구경하고, 새로운 동맹이나 거래처를 찾도록 유도합니다.
    
- **건축 장려:** 단순히 광질만 하는 서버가 아니라, 멋진 건축물이 늘어나는 서버가 되도록 '건축 행위' 자체에 보상을 줍니다.

## 5. 이벤트 리스너 및 연동 가이드 (Technical Implementation)

`Towny` 플러그인의 API와 Bukkit 이벤트를 조합하여 구현합니다.

### 5.1 PlayerMoveEvent (이웃 방문)

- **최적화:** `PlayerMoveEvent`는 매우 무겁습니다.
    
    - `from.getBlockX() >> 4 != to.getBlockX() >> 4` (청크가 변경되었을 때만) 로직을 실행합니다.
        
- **로직:**
    
    1. 이동한 위치의 `TownBlock`을 가져옵니다 (`TownyUniverse.getInstance().getTownBlock(...)`).
        
    2. `townBlock.isHomeBlock()`인지 확인합니다.
        
    3. 방문한 타운의 이름을 유저 데이터(Set)에 저장하고 카운트를 올립니다.
        

### 5.2 BlockPlaceEvent (건축가의 꿈)

- **로직:**
    
    1. 블록 설치 시 위치가 `Towny` 구역인지 확인합니다.
        
    2. `TownyAPI.getInstance().isWilderness(loc)`가 아니어야 합니다.
        
    3. (옵션) `plot.getResident().getUUID()`가 플레이어와 같은지 확인하여 "남의 땅 테러/도배"가 아닌 "내 집 짓기"인지 구분합니다.
        
    4. 설치한 블록이 `Dirt`, `Cobblestone` 등 기초 블록이 아닌 `Planks`, `Glass`, `Concrete` 등 건축 자재일 경우 가중치를 줄 수도 있습니다.
        

### 5.3 AsyncPlayerChatEvent (소통)

- **로직:**
    
    1. `TownyChat` 플러그인을 사용 중이라면, 채팅 채널이 'Town' 모드인지 확인합니다.
        
    2. 단순 자음/모음(`ㅋ`, `ㅎ`)이나 2글자 이하의 짧은 채팅은 카운트에서 제외하여 스팸을 방지합니다.

1. **타운 간의 연결:** '이웃 방문' 미션을 통해 유저들은 자연스럽게 다른 타운의 건축 양식을 구경하고, "우리도 저렇게 짓자"는 동기를 얻습니다.

마지막 퍼즐인 **공통 미션의 카테고리 D. [특별 목적 (Special)]**을 구체화한 상세 기획안입니다.

    1. Citizens NPC(`Trait`)를 활용하여 우클릭 시 GUI 오픈.
        
    2. GUI에 아이템을 넣으면 인벤토리에서 삭제하고 `config.yml`의 `current_progress` 증가.
        
    3. `HolographicDisplays`를 이용해 NPC 머리 위에 **"현재 달성률: 45%"**를 실시간으로 띄워주면 참여율이 폭발적으로 증가합니다.

## 2. 특수 재화: 드림 스톤 (Dream Stone)

직업 활동(채광, 낚시 등)에서 매우 낮은 확률로 얻는 `드림 스톤`을, **주간 미션 올클리어 보상**으로도 소량 지급하여 "운이 없는 유저"도 노력으로 얻을 수 있게 합니다.

### 2.1 드림 스톤의 용도 (Usage)

이 돌은 돈으로 환산하기보다는 **"성장 한계 돌파"**에 사용됩니다.

1. **직업 도구 업그레이드:**
    
    - 광부: `Tier 2 강철 곡괭이` -> `Tier 3 미스릴 곡괭이` 제작 시 필수 재료.
        
    - 농부: `자동 파종기(Planter)` 제작 재료.
        
    - 사냥꾼: `엘리트 몬스터 추적 나침반` 제작 재료.
        
2. **스킬 슬롯 확장:**
    
    - 기본적으로 활성화 가능한 직업 패시브 스킬 수 제한을 늘림.

## 3. 유틸리티 보상: "일상의 활력소"

## 4. 기술적 구현 가이드 (Technical Implementation)

이 보상 체계를 실제로 구현하기 위한 플러그인 설정 및 로직입니다.

### 4.1 Citizen Point (CP) 데이터 관리

MySQL 없이 파일로 관리하거나, `LuckPerms`의 Meta 데이터를 활용할 수 있습니다. 가장 추천하는 방식은 **자체 플러그인의 `PersistentDataContainer(PDC)`**를 사용하는 것입니다.

Java

```
// DreamWork 플러그인 내부 메소드 예시

public void addCitizenPoint(Player player, int amount) {
    // 1. PDC에서 현재 포인트 로드
    PersistentDataContainer data = player.getPersistentDataContainer();
    NamespacedKey key = new NamespacedKey(plugin, "citizen_point");
    int currentPoint = data.getOrDefault(key, PersistentDataType.INTEGER, 0);
    
    // 2. 포인트 추가
    int newPoint = currentPoint + amount;
    data.set(key, PersistentDataType.INTEGER, newPoint);
    
    // 3. 랭크 승급 체크 (Promote Logic)
    checkRankUp(player, newPoint);
}

private void checkRankUp(Player player, int point) {
    // LuckPerms API 연동
    User user = luckPerms.getUserManager().getUser(player.getUniqueId());
    String currentGroup = user.getPrimaryGroup();
    
    if (point >= 500 && currentGroup.equals("default")) {
        // 방랑자 -> 거주민 승급
        user.setPrimaryGroup("resident");
        luckPerms.getUserManager().saveUser(user);
        player.sendMessage("§e[축하] §f시민 등급이 §a[거주민]§f으로 상승했습니다!");
        player.playSound(player.getLocation(), Sound.UI_TOAST_CHALLENGE_COMPLETE, 1f, 1f);
    }
    // ... 상위 등급 로직 반복
}
```

### 4.2 보상 지급 설정 (`rewards.yml`)

보상을 하드코딩하지 않고, YAML 파일에서 유연하게 수정할 수 있도록 구성합니다.

YAML


### 4.3 랭크별 혜택 적용 (`LuckPerms` & `Towny`)

- **LuckPerms:**
    
    - `/lp group resident permission set towny.command.town.join true` (거주민부터 타운 가입 가능)
        
    - `/lp group noble permission set essentials.workbench true` (귀족부터 휴대용 작업대)
        
- **Towny:**
    
    - Towny의 `townyperms.yml` 혹은 `config.yml`에서 랭크별 최대 플롯 수(`max_plots`)를 조절할 때, PlaceholderAPI를 지원한다면 `%luckperms_group%`을 활용하거나, 별도의 권한 노드(`towny.claim.limit.bonus.5`)를 귀족 그룹에 줍니다.

## 5. 결론: "동기 부여의 선순환"

이 보상 체계는 유저에게 다음과 같은 사이클을 만들어줍니다.

1. **접속(Routine):** "일단 접속해서 모닝 커피(이속 버프) 받고 시작하자."
    
2. **활동(Economy):** "커피 마신 김에 광질해서 돈 벌자. 번 돈으로 농부한테 빵 사서 미션 깨자."
    
3. **성장(Reward):** "오, CP 다 모았다. 드디어 [귀족] 달고 휴대용 작업대 쓸 수 있다!"
    
4. **목표(End-Game):** "드림 스톤 모아서 전설 곡괭이 만들고 닉네임 금색으로 바꿔야지."
    

이로써 **공통 미션 시스템(기획+보상+기술)**의 전체 그림이 완성되었습니다.

이제 이 설계를 바탕으로 **실제 플러그인 개발(Java)**이나 서버 세팅(플러그인 적용) 단계로 넘어가시면 됩니다.

혹시 **"미션 관리자(Mission Manager)" 플러그인의 핵심 코드 구조**나, **YAML 파일 파싱 로직** 등 개발 관련 구체적인 도움이 필요하신가요?
